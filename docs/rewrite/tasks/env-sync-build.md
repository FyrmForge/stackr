# Env sync: build plan

Status: built 2026-10-05 (Sonnet workers), on the rig as v0.6.0-dev.10 (QA passed). Design: `docs/features/env-sync.md` (its
Decided section is fixed; this file decides the build).

## How the work runs
- One worker per package; a package owns its files and touches no other.
- Every package ends green on `make test`, `make lint`, `make templint` (web),
  with one test per behaviour listed. No commits by workers.
- Waves: A and B in parallel, then C, then D and E in parallel, then F.
- Generated files (`*_templ.go`, `docs/openapi.json`) are regenerated by
  their tool, never edited by hand.
- Paths below are under `internal/service/internal/` unless they start with
  `internal/`, `cmd/` or `docs/`.

## Diff model
- Tiles match by slug. Three tags: `new` (in source only), `edited` (in
  both, differs), `removed` (in target only). An unchanged tile has no tag.
- `want` for an Edited tile is the source row with the target's `ID`,
  `StackID`, `EnvironmentID`, `Name`, `ImageRef`, `GitBranch`, `Paused`,
  `CreatedAt`, `UpdatedAt`. Edited = `tile.Diff(target, want).Any()`, or for
  a managed tile the instance's `Allow` or `EnvPairs` differ.
- `want` for a New tile is the source row with `ID` cleared, `StackID` and
  `EnvironmentID` of the target, `Paused` false; on a `from: branch` target
  `GitBranch` = the target's `FromBranch`. Image copied (a tile needs one).
  Managed: `Managed.Create(tileID, engine, "stackr", "")`, then allow and
  pairs through `planInstance`. Slice: `provision_from` copied; `planSlice`
  blocks an unreachable target.
- Removed: `planDeletes` then `Remove`; a managed tile's instance volumes are
  orphaned by `Remove`.
- Blockers: `tile.Validate` on every want row; kind change (`planUpdate`);
  engine change (`planUpdate`); source change, same kind
  (`tile.Builds(old) != tile.Builds(want)`): "tile x changes its source
  (image to git build); remove it in one sync and add it back in the next";
  in-use managed tile (`planDeletes`); unreachable slice target
  (`planSlice`); dangling: a tile in the result whose `depends_on`,
  `${{ tile.<slug>.* }}` ref or `slice_access` names a slug not in the
  result.
- Params: for each `params.KindParam` ref in a kept New or Edited want row
  (env values and command, as `graph.refs` reads them): key
  `Slug+"."+Name`; set in the source env and not in the target env: a plain
  param is copied with its value (`params.Entry`, Change kind `param`), a
  secret is a warning naming the tiles that read it, unless set at stack or
  org scope (shared, nothing to do). A name already set in the target keeps
  its value.
- Volumes: for each `slug:/path` mount of a kept New or Edited want row,
  the source env's volume row (`InstanceID == nil`) with that slug: missing
  in the target env, or `MaxSizeMB` differs, or orphaned there: `Declare`
  (Change kind `volume`). A target env volume mounted only by Removed tiles
  and by nothing in the result: `Orphan` (Change kind `orphan`). Nothing
  else is orphaned. `planVolumes` is not reused: it orphans every volume the
  file lacks.
- Display: an `update` row for `env` or `build_args` carries the signed key
  diff in `Note` (`signedDiff` over sorted keys, "+KEY −KEY"); values never
  appear. Commands never appear (`shownValues` has none).
- Warnings: a New git-built tile ("api has no build in staging yet; it
  starts on the next push to main" on a branch env, "... with the next
  release promoted here" on a ladder env); a want row with `Privileged` or
  `Devices` where the target row had neither ("api runs privileged or with
  host devices in staging after this sync"); an Edited managed tile whose
  `Effects` carry `tile.Redeploy` ("db restarts to take the new settings");
  an unset secret (above); orphaned volumes come as `Change` notes.
- Deploy rule, as a tile edit: a New tile is deployed unless it builds from
  git (nothing built yet); an Edited tile, and a consumer of a new or moved
  slice, is redeployed only when it has replicas (`Tiles.Replicas`). Every
  deploy is `deploy.Flow.Redeploy`. No sync release; a first-run derive by
  `Redeploy` is the deploy's own, as today.
- Drop: a dropped slug's entry in the result is the target's own live
  state. New dropped: no entry. Edited dropped: the target row. Removed
  dropped: the target row stays. One rule feeds `planDeletes`, `refsTile`,
  `sliceTarget` and the dangling check.
- Sig: hex of `sha256` over the JSON of the no-drop work (creates rows,
  updates new rows, deletes ids, params entries, declare map, orphan ids,
  instances map), first 16 chars. Any change to what would be written moves
  it; the display does not matter.

## Packages

### A. Sync plan and apply (flow). Wave 1.
Files: `flow/promote/sync.go`, `flow/promote/sync_test.go` (new);
`flow/promote/plan.go`: only the `Release` json tag gains `omitempty`.

Contract (all in package `promote`):
```go
type Sync struct {
    Plan                  // Stack, Env, Changes, Blockers, Warnings, Deployed, Removed
    From  string     `json:"from"`  // source env slug
    Tiles []SyncTile `json:"tiles"` // every tagged slug, sorted, drops included
    Sig   string     `json:"sig"`
}
type SyncTile struct {
    Slug    string `json:"slug"`
    Kind    string `json:"kind"`
    Tag     string `json:"tag"` // new | edited | removed
    Dropped bool   `json:"dropped,omitempty"`
}
// SyncPlan is the dry run of making envID's setup match fromID's, minus drop.
func (f *Flow) SyncPlan(ctx context.Context, envID, fromID string, drop []string) (*Sync, error)
// SyncApply re-plans, refuses on drift or blockers, then applies. keep are
// the slugs to sync (drop = tagged minus keep); sig is the review's.
func (f *Flow) SyncApply(ctx context.Context, envID, fromID string, keep []string, sig string,
    log io.Writer, swap func() error) (*Sync, error)
```
- `syncWork(ctx, e, src store.Environment, st store.Stack, drop []string) (*Sync, *work, error)`
  is the one planner; `SyncPlan` calls it once with no drop (for `Sig` and
  `Tiles`) and again with drop when drop is not empty. `SyncApply` calls it
  with no drop, compares `Sig` (`errs.Conflictf("the environments changed
  since the review; review again")`), computes drop = tagged slugs not in
  keep, plans with drop, refuses when `Blocked()` (Conflict joining the
  blockers, as `Apply`), refuses when `Changes` is empty (Conflict "nothing
  to sync"), logs each `Change.Line()`, calls `swap`, then `applySync`.
- Blockers first, then return: `e.ID == src.ID` ("an environment cannot
  sync from itself"), `st.ConfigRepo != ""` ("the stack is managed by its
  config file; change the file instead"), `src.StackID != e.StackID`.
- `work.re` is a thin `ResolvedEnv`: `Tiles[slug] = TileConf{Type, Engine,
  Allow, EnvPairs, Env, Command}` from the row and its instance (`thinConf`),
  nothing else. It exists for `planUpdate`'s engine check, `planInstance`,
  `sliceTarget`, `refsTile` and `planDeletes`. Rows are never built through
  `toRow`.
- Order inside `syncWork`: lists and instances; tags; apply drops to the
  result set; for each result slug in sorted order: New kept: build want,
  `tile.Validate` (block on error), `creates`, `redeploy[slug] = true`,
  Change `create`, then `planInstance` or `planSlice` with `exists=false`;
  Edited kept: source-change block, `planUpdate(old, want, tc)`, then
  `planInstance` or `planSlice` with `exists=true`; unchanged or dropped:
  nothing. Then the sliced-consumer loop (copy from `planConfig`),
  `planDeletes(live)`, params, volumes, dangling check, warnings, the env
  Note pass, `Tiles`.
- `applySync(ctx, w, log)`: `Params.Merge`; `Volumes.Declare` each (sorted);
  `Volumes.Orphan` each; `Tiles.Create` each create (managed: then
  `Managed.Create(t.ID, w.re.Tiles[slug].Engine, "stackr", "")`);
  `Tiles.Update` each update; `applyInstances`; `Remove(deletes)`; `d.Sync`
  when `w.sync`; then the rollout: `topo(slugs, depsOf(live))` over the live
  tiles after the writes, three `rolloutPass` passes, for each slug with
  `redeploy`: skip a created git-built tile (log "api: no build yet, not
  deployed"), skip a non-created tile with no replicas, else
  `d.Redeploy(ctx, t.ID, log, nil)` and append to `deployed`. `Deployed` and
  `Removed` filled as `Apply` does.
- Tests (`sync_test.go`, reuse `setup` from `promote_test.go` and clear
  `ConfigRepo` on the stack row with `s.Stacks.Update`; tiles made through
  `d.Tiles.Create` with rows that pass `Validate`): identical envs give no
  changes and no tiles; image tag differs only: no changes; New image tile
  tagged `new`, created, deployed (fake run id); New git tile: created,
  warning, not deployed; Edited port: `update` row, target keeps image and
  paused, redeployed only when running; param copied (plain), secret warns;
  config-bound stack blocks; same env blocks; in-use managed blocks;
  unreachable slice blocks; dangling depends_on after dropping the New dep
  blocks; drop of a Removed tile keeps it; Sig changes when the source row
  changes and `SyncApply` with the old sig is a Conflict; Removed managed
  tile orphans its instance volume.

Contract (package `service`):
```go
type SyncPlan = promote.Sync
type SyncTile = promote.SyncTile
// EnvSyncPlan mirrors PromotePlan.
type EnvSyncPlan struct {
    Plan      *SyncPlan `json:"plan"`
    CanDeploy bool      `json:"can_deploy"`
}
// EnvSyncSources says whether envID can sync and from where.
type EnvSyncSources struct {
    Can     bool
    Why     string        // "" when Can; else the reason, one sentence
    Default string        // the default source's slug; "" when none
    Envs    []Environment // every other env of the stack, ladder order then the rest
}
func (o *Orchestrator) EnvSyncSources(ctx context.Context, envID string) (EnvSyncSources, error)
func (o *Orchestrator) PlanEnvSync(ctx context.Context, envID, from string, drop []string) (EnvSyncPlan, error)
func (o *Orchestrator) EnvSync(ctx context.Context, envID, from string, keep []string, sig string) (Job, error)
func (o *Orchestrator) EnvSyncCanvas(ctx context.Context, envID, from string, drop []string,
    show GraphShow) (GraphView, EnvSyncPlan, error)
```
- `from` is the source env's slug, resolved with `o.envs.GetBySlug(ctx,
  e.StackID, from)`; not found is `errs.ErrNotFound` (404).
- `EnvSyncSources`: `Can=false, Why` when `Stack.ConfigRepo != ""` ("Managed
  by the stack file.") or the stack has one env ("The stack has one
  environment."). `Default`: `o.envs.Below(e)` when found, else the first
  env of `o.envs.Ladder` that is not `e`, else the first of `o.envs.List`
  that is not `e`. `Envs` = `Ladder` then the rest of `List`, minus `e`.
- `PlanEnvSync`: `o.promote.SyncPlan(ctx, e.ID, src.ID, drop)`; `CanDeploy
  = !Blocked() && len(Changes) > 0`.
- `EnvSync`: `SyncPlan` with no drop; `Blocked()` → `errs.Conflictf` joining
  the blockers; `Sig != sig` → Conflict "the environments changed since the
  review; review again"; no `Changes` → Conflict "nothing to sync"; then
  `o.enqueue(ctx, kindEnvSync, envSyncJob{EnvID, FromID, Keep, Sig}, lock...)`
  with the lock set of `enqueuePromote` (env id and every target tile id).
- `EnvSyncCanvas`: `PlanEnvSync`, then `graphIn(ctx, scope, show, true)`
  with `in.Sync` from `Plan.Tiles` (dropped tiles excluded) and `in.New` =
  the create rows; the flow exposes them as `Sync.Creates []store.Tile`
  with `json:"-"` (A adds this field; C reads it). Returns the view and the
  plan.
- `jobs.go`: `kindEnvSync jobs.Kind = "env-sync"`; `envSyncJob{EnvID, FromID
  string; Keep []string; Sig string}`; handler mirrors `kindPromote`:
  `plan, err := o.promote.SyncApply(ctx, p.EnvID, p.FromID, p.Keep, p.Sig,
  r.Log, r.Swap)`; when `plan != nil`: `errors.Join(err,
  o.dropRuns(plan.Removed), o.afterDeploy(ctx, plan.Deployed, true))`.
  `afterDeploy(…, true)` reloads the scheduler and queues on_deploy runs.
- Tests (`servicetest.New`, `e.Tile` gives stack shop with env dev and image
  tile api; create a second env staging; run a job by polling `GetJob` as
  `TestEnvReleases` does): default source is the env below (staging from
  dev) and the bottom rung for a branch env; `Can` false on one env;
  `Can` false when `SetConfigRepo` bound (use `e.Connector`); stale sig is
  a Conflict and queues nothing; blocked plan is a Conflict; the job creates
  and deploys a New image tile (fake Docker shows a container); Edited keeps
  the target's image, branch and paused; Removed orphans the instance
  volume; a plain param is copied; `EnvSyncCanvas` tags the card and adds
  the ghost.

## Decided (build)
- New git-built tile: created, not deployed, with a warning naming the
  branch (branch env) or the next promoted release (ladder env). Nothing is
  built in the target; a push to a branch env builds every git tile of the
  env (`flow/promote/push.go`), so it starts on its own.
- Drift: the deploy posts the review's `sig`, a hash of the full no-drop
  work, not of the displayed rows. The review shows no values, so a value
  edit between review and deploy must still refuse; hashing what would be
  written does that. Checked at enqueue and again in the job.
- Params: a missing plain env param read by a kept row is copied with its
  value; a secret is a warning only; a name set in both keeps the target's
  value; stack and org params are shared and never touched.
- `replicas`, `limits`, `update_policy`, `watch_paths`, `tag_policy`,
  `shared_net`, `files`, `slice_access` sync as settings: everything
  `tile.Diff` compares except `image`, `branch`, `paused` and kind. Drop the
  tile to keep the target's.
- `privileged` and `devices` sync with a warning. The chip on the card and
  the warning line are enough; blocking would make a host tile unsyncable.
- PR envs are allowed as source and target; a branch or PR env defaults to
  the ladder's bottom rung. A New cron arrives unpaused: paused is never
  synced and false is the create default.
- Editing a managed tile's settings restarts it (`tile.Effects` gives
  Redeploy for a managed tile); the review warns. Allow and env pairs are
  row writes only.
- Open point 8 rejected: no `SetParams`. The job merges params through
  `leaf/params` inside the flow, as promote does. `SetParams` would queue a
  deploy job per running tile behind the sync's own lock, and the only tiles
  that read a copied param are the New and Edited rows the sync deploys.
- The apply lives in `flow/promote` (`SyncApply`), not in service through
  orchestrator verbs. The verbs enqueue jobs (`UpdateTile` queues a deploy,
  `SetParams` several) while the sync job holds the env lock, and the pieces
  the apply needs (`applyInstances`, `Remove`, `topo`, `rolloutPass`) are
  already in the package. The job handler mirrors `kindPromote`.
- Diff is row to row. `want` is the source row with the target's identity
  and version fields; `work.re` is a thin `ResolvedEnv` for the helpers that
  read it. A round trip through `toRow` and `Validate` re-encodes
  `EnvJSON` and the list columns and would show phantom Edited rows.
- Drop means "the target's own state for that slug": a dropped New has no
  entry, a dropped Edited keeps the target row, a dropped Removed keeps the
  tile. One rule feeds deletes, refs, slice targets and the dangling check.
- Dangling blocks: a tile in the result naming a slug not in the result
  through `depends_on`, a tile ref or `slice_access`. A deploy would park or
  fail on it later; the plan says so first.
- Deploy rule follows `UpdateTile`: New tiles deploy unless git-built;
  Edited tiles and slice consumers redeploy only when they have replicas.
  All through `deploy.Flow.Redeploy`, which owns pins and the first-run
  derive, so sync adds no release logic.
- Volumes: declare what kept rows mount when missing, resized or orphaned;
  orphan only what Removed tiles alone mounted. `planVolumes` is not reused
  because it orphans everything the file does not declare.
- `:from` is the source env's slug, resolved inside the stack by the
  service. The CLI takes a slug already; a cross-stack env cannot be named.
- Sources are an in-process verb for the web; no API route. The CLI
  requires `--from`.
- The review's `env` and `build_args` rows carry the signed key diff, never
  values; commands never show.
- `Sync` embeds `Plan`; `Plan.Release` gets `omitempty` so a sync plan shows
  no release. Promote plans never have release 0, so nothing changes there.
- Ghosts are `tileCard` with id `sync:<slug>`, static, no edges. A managed
  ghost shows no engine detail; its kind chip says database.
