# Shard: CLI client-side rules (lens 2, surface: `internal/cli/cmd`)

Question: which business rules does the CLI apply before or instead of the API.
CLI paths are under `internal/cli/cmd/`. API paths are under
`internal/stackrd/handlers/api/v1/`. Web paths are under `internal/stackrd/handlers/web/handler/`.
`cmd/stackr/main.go:12` is entry only (`os.Exit(cmd.Execute())`), no rules.
`_test.go` files skipped. Round 1 (`02-findings.md`) has the CLI as a file:line
column only; this shard goes one level down. Tiles rows that round 1 already
covers are cross-referenced, not re-derived.

Shared plumbing that is not a business rule but shapes every row: `Confirm`
(`root.go` runtime, `Runtime.Confirm` in runtime.go:1936-1955) skips on `--yes`,
prompts on a TTY, refuses on non-TTY; `usagef` exits 2; `PromptSecret` reads env
or masked input (runtime.go:1970).

## 2. Findings

- **Create tile, A.** `tileCreateCmd` blanks `Schedule`, `Command`, `TimeoutMinutes` when no `--cron`/`--function` is passed (tile.go:126-129). `createApp` never checks these against the kind: it copies `in.Schedule`, `in.Command`, `in.TimeoutMinutes` into the row for a service too (apps.go:150-153). A raw API call or the web form can store a schedule on a service; only the CLI cannot. The tiles shard records the config path refusing `command` on kinds without `AllowsCommand` (stackconf.go:1018), so the rule exists in one of three server-side copies and in the client.
- **Update tile settings, A (footgun, cross-ref tiles).** `--cpu 1.5` without `--memory` sends `limits: {cpu: 1.5, memory_mb: 0}` (tile.go:253-263, `orZero` 309) and `patchApp` writes both (apps.go:251-253). Same for `--dockerfile` alone clearing `build.context` to "" (tile.go:247-252, apps.go:248-250), and `createApp` defaults empty context to "." only on create (apps.go:141-144), not on patch. The CLI help documents the coupling (226-230). This is a consequence of the API's nested-object patch shape; the rule "a limit pair is atomic" is not written anywhere server-side.
- **Metrics, A (minor).** CLI refuses an unknown `--range` with exit 2 (lifecycle.go:191-195); `appMetrics` treats anything not `6h`/`24h` as 1h (lifecycle.go:137-142). Same parser copied a third time in web `components.MetricRange` (tiles shard).
- **Promote, A.** `pickRelease` (promote.go:131-196) is the only place that turns `head`, `latest`, `--from <env>` and a short sha into a commit, and the only place that refuses an ambiguous prefix. `promote` (releases.go:137-144) and `Applier.Promote` (apply.go:155-183) accept any non-empty string and check only that the env is a rung above the default. Neither checks the commit is built. The web passes `Force: true` unconditionally when a plan is attached (releases.go:322-323); the API body defaults `force` to false (releases.go:124-125); the CLI exposes `--force` defaulting false (promote.go:124). Three force policies for one job.
- **Delete env, Reset env, A.** CLI sends `force = --force || --yes` (promote.go:239-240, 274), so `-y` in a script tears down running tiles, which the flag help does not say (251). API refuses a running env unless `force:true` (envs.go:74-78, 100-104). Web `DeleteEnv` has no running check at all; the typed-slug confirm is the whole gate (project/handler.go:386-389). Web also refuses on `ConfigManaged` (376) where the API `deleteEnv` gate is `managedGuard` via `requireEnvWrite` (not checked).
- **Delete instance, A.** `infraRmCmd` calls `DeleteDB(t.ID, true)` on every path (infra.go:1559). `deleteDB` refuses by default while consumers hold slices and requires `force=true` to destroy them (databases.go:425-433). The CLI replaces that server rule with a prompt that lists the slices (1551-1557), and `--force` or `-y` skips the prompt (1532-1537), so `stackr infra rm <path> -y` destroys consumer-held slices without the API ever being asked. The web db handler was not checked.
- **Member set role, A (minor).** `validRole` coerces any unknown role to `member` (members.go:232-237). The CLI checks only that `--role` is non-empty (members.go:358), so `--role admin` succeeds and prints `is now member` (376).
- **Org plan approve, parity gap.** No `GET /org-config/plans/:id` (v1.go:242-246), so the CLI confirms blind (org.go:647-652) while the stack path reads the plan first and confirms only when destructive (plan.go:671-680).
- **Variables get, output shaping.** The API reveals secret values to a `secrets:read` key (variables.go:53-58, 76); `vars get` masks them again in both table and JSON (vars.go:1105-1110). Deliberate (comment 1107-1108), recorded so nobody reads the CLI JSON as the API's truth.
- **Name resolution, duplication.** The CLI resolves names by fetching `/apps` (and `/dbs`) and scanning (helpers.go:132-223, backup.go:16-35) although `slugpath.go:94` already resolves `org:stack:env:tile` server-side. Four client-side resolvers with slightly different fallbacks (db name matches only inside the linked stack, helpers.go:184; bare id retries unscoped, 213-221).

## 3. Service implications

Mapped onto `02-findings.md` section 2 candidates. Every CLI-only rule above is a
rule the service must own so the CLI can drop it.

- **2.3 TileService.** `Create` owns the kind-key rule (schedule/command/timeout only on cron/function) so apps.go:150-153 and tile.go:126-129 both go; `validateTile` (stackconf.go:995) is already the widest copy. `Update` takes the full tile, so "limits is an atomic pair" and "build is an atomic pair" become facts of the merge at the API edge, and the CLI stops doing `orZero`. `Delete` guards are the tiles shard's.
- **2.3 TileLifecycleService, TileTelemetryService.** One `Metrics(window)` parser replaces lifecycle.go:137-142, lifecycle.go:191-195 and the web range switch. Rollback tag trim lives in `Rollback`. Port range check (deploy.go:1069, forward.go:186) is one `ValidPort`.
- **2.4 ReleaseService.** `Resolve(stack, ref) (commit, error)` for `head`, `latest`, `from:<env>`, short-sha prefix with the ambiguity rule, moved out of promote.go:131-196 so the API and web can accept the same refs. `Promote(env, commit, force)` owns the force policy once; today web (`true`), API (body), CLI (`--force`) each decide.
- **2.4 DeployService.** Export a terminal predicate for deployments (the CLI hard-codes `done`/`error`/`cancelled` at deploy.go:919; `WorkItem.Done` at models.go:741 exists for work items, none checked for `Deployment`).
- **2.2 EnvironmentService.** `Delete(env, force)` and `Reset(env, force)` with the running check in one place; the web copy (project/handler.go:370-392) gets the check it lacks, the CLI stops mapping `-y` to force or documents it.
- **2.1 ManagedInstanceService.** `Delete(instance, force)` keeps the consumer-held refusal (databases.go:425-433); the CLI passes the user's `--force`, not a constant. Kind gates (instance vs slice) for get/ls/set/fork/public/provision/attach become `SliceService` and `ManagedInstanceService` preconditions instead of six CLI `t.Kind !=` checks (infra.go:1389, 1426, 1466, 1618, 1682, 1722; tile.go:415).
- **2.4 PlanService (org side).** Add `GetOrgPlan` so org.go:647-652 can confirm on `Destructive` like plan.go:671-680. Include-path and bundle-size rules stay in the CLI (they guard its own disk read) and in the API body cap.
- **2.5 MemberService.** `SetRole` refuses unknown roles instead of `validRole` coercing (members.go:232-237); the CLI drops its own check.
- **2.7 DomainService, DomainResourceService.** Owner defaulting for stack-level resources (domain.go:611-616) and host-to-id lookup (647-660) become `Create(level, owner?)` and `Resolve(hostOrID)`; TLS pair rule stays in `PatchDomain` (lifecycle.go:223-231), CLI pre-check can go.
- **2.9 VolumeService.** Default name from mount path (tile.go:644-650) moves into `Create`, or is dropped; today only the CLI has it.
- **2.10 BackupScheduleService, BackupDestinationService.** Required-field and default rules already live server-side (backups.go:54-55, 181-193, 202); CLI duplicates are removable. Restore polling uses `WorkItem.Done`.
- **2.8 PREnvService.** A sparse `Update` replaces the CLI read-merge-write (lifecycle.go:625-647) forced by whole-object PUT (lifecycle.go:408).
- **2.2 VariableService, 2.5 AccessService.** Generate, length and never-overwrite rules are already server-side (variables.go:152-165). Masking policy is an API-edge concern; the CLI's second mask (vars.go:1105-1110) is a client choice and stays.
- **Cross-cutting: resolver.** A single server-side name/path resolver (slugpath.go:94 already exists) lets helpers.go:132-223 and backup.go:16-35 collapse to one call.
