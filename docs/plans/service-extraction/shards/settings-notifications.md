## 3. Drift findings

1. **Set org defaults — class A.** Web `web/org/registry.go:262` returns 409 when `o.ConfigManaged()` and requires owner (`ownedSettingsOrg` `web/org/settings.go:217-224`). API `api/v1/settings.go:47-57` has no config-managed check and accepts any org **member** via `requireOrgWrite` `api/v1/auth.go:300-309`. Config then overwrites the blob on the next apply (`orgconf.go:687-691`). Same operation, two gates, the CLI (`defaults.go:83`) gets the loose one.
2. **Set stack / env defaults — observation, not cross-surface drift.** Neither web (`project/handler.go:1022,2542`) nor API (`settings.go:58-78`) checks `ConfigManaged`, while config `apply.go:932-937,955-964` owns `defaults:` and replaces the whole blob. Consistent with each other, inconsistent with the org level (finding 1). One policy belongs in SettingsService.Set.
3. **Set server defaults — class A.** Web `web/server/handler.go:322` also renames the server from the form with no validation (empty name stored) and addresses any `:id` server row; API `settings.go:42` is fixed to `"local"` and never sets `Name`. Rename has no API/CLI at all.
4. **Approve/reject/plan org config — class A (role).** Web owner-only (`web/org/config.go:113` via `ownedSettingsOrg`); API owner-or-member (`api/v1/orgconfig.go:28,111`). Also web swallows an Apply failure into a flash and returns applied=false (`config.go:214-216`), API answers 422 (`orgconfig.go:126`). Same guard `Status != "pending"` written twice (`config.go:208,227` / `orgconfig.go:122,137`).
5. **Invite mail — class B, cross-shard.** Web invite path sends the mail (`web/org/members.go:286-290`); `handlers/api/v1/*.go` contains no reference to `mail` (grep), so `POST /orgs/:id/invites` (`v1.go:195`) creates the invite and nobody is told. Mailer is env-only (`infra/mail/mail.go:37`), no settings surface exists. Owned by orgs+members shard; recorded here as the only mail write.
6. **Proxy escape hatches — duplication, no drift.** `proxyEntries`/`saveProxyEntries`/`validYAML` (`web/settings/proxy.go:25,34,45`) and `proxyEntriesMap`/`saveProxyEntriesMap`/`yamlValid` (`api/v1/proxycfg.go:39,48,59`) are byte-for-byte twins. API drops the `EnsureTraefik` error (`proxycfg.go:93`), web logs it (`proxy.go:124`). Delete does not `Slugify` the name while write does, on both surfaces (`proxy.go:138,158`; `proxycfg.go:103,120`).
7. **Stack export — duplication.** The static-env ladder-order rebuild is copy-pasted: `web/project/releases.go:358-369` and `api/v1/config.go:272-283`.
8. **Parity doc stale — `ui_edits` default.** `docs/surface-parity.md` marks web and API/CLI ✅ for "`ui_edits` default"; the only writer of `Org.UIEditsDefault` is `config/orgconf/orgconf.go:676-677`. `settingKeys` (`api/v1/settings.go:202`) has no `ui_edits`, and no web handler sets it (grep `UIEditsDefault =` in `handlers/`).
9. **Server-only knobs accepted at every level — observation.** `settings.Merge` (`settings.go:192-195,228-234`) folds `build_node` and the four concurrency keys at org/stack/env too, and `settingKeys` exposes them on `PATCH /orgs|stacks|envs/:id/settings`; `Resolve` reads them at the server level only per the comments (`settings.go:37-46`). Config `DefaultsConf` (`stackconf.go:185-198`) omits them, so a config apply wipes such a stray override silently (`apply.go:933`). Same on web and API, so not A; a SettingsService should refuse them below server.
10. **Node lifecycle rules live only in the handler.** Pinned-tile drain refusal (`nodes.go:279-299`), manager-removal refusal (`:335`), remove ordering drain → RemoveNode → BurnServerJoinKeys → DeleteServer (`:346-363`), "not joined" group guard (`:382`), agent `Ensure` after AddNode (`:71`). None is in `infra/nodes.Service`; an API for nodes (parity hole 1) would have to re-derive all five.
11. **Layering — `infra/*` imports `handlers/notify`.** `infra/deploy/engine.go:533`, `infra/jobs/jobs.go:421`, `infra/imagewatch/watcher.go:142`, `infra/cigate/cigate.go:117` call a package under `handlers/`. Not class D (no docker type crosses upward) but the inverse dependency the target layout forbids.
12. **Notification centre GET has a write.** `web/notification/handler.go:265` marks everything read inside the page render and drops the error; `:288` drops the count error. Web-only, so no drift; noted as logic-in-handler.
13. **DNS-01 provider stored unvalidated.** `web/settings/handler.go:373-376` writes `dns_provider` and `dns_env` verbatim; the only consumer `infra/proxy/proxy.go:88-89` is what discovers a bad value, after a background `EnsureTraefik` (`handler.go:379`) whose failure is only logged. Web-only.
