## 3. Drift findings

1. **Create environment — A.** Web refuses slugs `settings`/`list` (`P:322`) but accepts an empty slug and a duplicate slug; API refuses empty (`stacks.go:106`) but accepts `settings`/`list`/home and duplicates; API copyEnv is the only one with all three rules (`envs.go:132-137`); config derives the name and skips existing (`apply:907-919`); PR hook applies none (`prhook/handler.go:501-510`). Four creators, four rule sets.
2. **Clone environment — A.** Same operation, web `CreateEnvironment(base_env_id)` vs API `copyEnv`: only the API checks duplicate slug (`envs.go:135`) and `slug == ""`; web reloads schedules only on clone (`P:352`), API always (`envs.go:150`).
3. **Reset environment — B.** Web re-plans after teardown (`planner().RunAll` `P:436`) because the live plan is stale; API `resetEnv` (`envs.go:91-113`) tears down and returns. A CLI `env reset` leaves a stale pending plan whose Apply reads as "finish" instead of "rebuild".
4. **Set env colour — A.** Web refuses on a config-managed stack (`P:2126` managedErr); API `patchEnv` has no managed check (`envs.go:162-189`). The next apply overwrites it anyway (`apply:958-962`), so the API accepts a write that cannot stick.
5. **Set env apply policy — A.** Web: only on config-managed stacks (`P:853` 409 otherwise), invalid value silently coerced to `""` (`P:857-860`), runs a plan when a branch is set (`P:866`). API: any stack, invalid value 400 (`envs.go:182`), no plan. Config: `apply:962` writes `re.ApplyPolicy` unconditionally, so a policy set from the panel or CLI on a managed stack reverts to `""` on the next apply unless the file also declares it. The panel offers the field only on managed stacks, which is exactly where the file wipes it.
6. **Stack / env variable set — A.** Name rule: web `secretNameRe` (`P:2293`, `P:2591`, org copy `ORG:410`); API `writeVars` accepts any non-empty name (`variables.go:120`). A CLI `vars set 'A B=1'` stores a name the panel would refuse and a `${{ stack.A B }}` reference cannot read.
7. **Stack / env variable set and delete — B.** Web `SaveStackVar`/`DeleteStackVar`/`SaveEnvVar`/`DeleteEnvVar` call `replanAsync` (`P:2302, 2325, 2599, 2629`) so a config-managed stack's plan reflects the new value (unset-secret inputs, `unsetSecrets` `P:1997`); API `writeVars` (`variables.go:116-197`) never re-plans. `stackr vars set` on a managed stack leaves the pending plan reporting the secret as unset.
8. **Generate a secret — A.** Web `components.VarValue` (`varsedit.templ`) mints 32 chars and **overwrites** whatever is stored; API `writeVars` skips a name that already has a value (`variables.go:149-153`) and honours `length`; config `ensureSecrets` skips too (`apply:1799-1809`). The panel's generate button is a rotation; the API's and the file's are not.
9. **Tile plain variables — A and B.** Web `SaveEnv` uses `editGate` and stages under `ui_edits: stage` (`APP:1172-1191`); API `putVars` uses `rejectManaged` (`variables.go:91`), 409 on the same stack (same shape as the calibration patchApp finding). Web redeploys a running service after a live save (`engine.Enqueue` `APP:1204`); API writes the blob and rows and stops (`variables.go:109` "deploy to apply"). A CLI `vars set --tile` on a running tile changes nothing until someone redeploys.
10. **Tile secret variable — A.** Web `SaveSecretVar` has no gate at all (`APP:1089-1108`) and no name regex; API `putVars` refuses the whole write on a config-managed stack (`variables.go:91`), including secrets, which the file never holds. Web `DeleteVar` (`APP:1110`) gates only blob names; API deletes anything omitted.
11. **Drop-link submit — B.** `sharelink.Submit` (`sharelink:117-158`) writes stack variables and audits them but calls neither `deploy.ClearWaiting` nor a replan, both of which `SaveStackVar` does (`P:2301-2302`). A tile parked "Waiting for X" stays parked after the client pastes X through the link; the comment at `sharelink:129-131` admits the replan half.
12. **Promote — duplication, no class.** `promoteEnv` is byte-identical in `R:171-190` and `api/releases.go:170-189`. Web hardcodes `Force: true` on the plan job (`R:325`); API passes `in.Force` (`releases.go:158`). Same rule, two copies, one behavioural difference that is documented as intentional.
13. **Env list return shape — no class.** API `envOut` (`types.go:44`) carries id/name/slug only; type, colour, position, apply_policy and config_branch exist on the row (`models.go:204-226`) and are shown on the web settings page (`P:2089`). A CLI cannot see the ladder order or which env is ephemeral.
14. **Env network — reference only.** No surface exposes claim/release as an operation; `envops.Teardown` (`envops:517,568-583`) is the only release path and is shared. Thirteen handler call sites reach `envnet` directly (listed in the table row); all are name/scope reads except two `TearDown` calls (`api/helpers.go:130`, `APP:1632`) that belong to the tiles shard.
