`internal/cli/` or `cmd/`. `web/…` = `handlers/web/…`, `api/…` =
`handlers/api/v1/…`. Calibration rows (tile settings connector check,
`wait_for_ci` coercion) are referenced, not re-derived.

## 3. Drift findings

- **Delete registry — A.** `api/registry.go:334-338` refuses a `Managed` row with 409; `settings/handler.go:657` deletes whatever id arrives, no load, no managed check; only the template hides the button (`settings.templ:126`). A crafted POST removes the managed row; boot then recreates it with a fresh password (`infra/registry/registry.go:41-55`), invalidating every org's derived system credential until `EnsureSystemCredential` re-records it (`token.go:285-309`).

- **Set managed registry domain — B.** Web runs `registry.EnsureManaged` when a domain is set (`settings/handler.go:616-622`) then `px.WriteRegistry` (`:624`); api `patchRegistry` only `px.WriteRegistry` (`registry.go:320-324`). Also rule drift folded in: web 400s without a managed registry (`:609-611`) and touches only the managed row; api patches any registry by id, storing an unused `Domain` on external rows and accepting `username`/`password` changes no other surface offers (`:311-316`).

- **Create org registry credential — A.** api `requireOrgRegistry(write)` returns 503 when `GetManagedRegistry` is nil (`api/registry.go:36-42`); web `CreateRegistryCredential` never looks the registry up (`org/registry.go:165-188`, deliberate per `:28-31`). Same input, one surface refuses.

- **Delete image tag — A.** Name: api unescapes, accepts short or namespaced, checks `ValidRepoName` and `ValidTag` (`api/registry.go:147-166`, `:209-211`); web requires the namespaced form and validates neither (`org/registry.go:223-226`). In-use: api `tagInUse` matches `HasSuffix("/"+name+":"+tag)` or exact (`:252`); web `liveTags` keys on the text after the first `/` (`:152`), so a stored `ImageTag` without a host segment is protected by api and deletable from web. Ordering: web checks in-use before confirming the registry exists (`:227` vs `:230`), api the reverse.

- **Set tile connector — A (extends calibration).** Beyond web-drop vs api-400: the config surface refuses a foreign id at plan time only when the org lookup succeeded (`plan.go:885` `len(s.OrgConnectors) == 0` short-circuits to allow), and the engine re-checks and silently returns nil (`githubapp.go:326-329`) so the clone runs unauthenticated. Four copies of one rule, two of them fail open in different ways.

- **Set PR env settings — A.** Web `SavePREnv` (`project/handler.go:2647`) and api `putPREnv` (`lifecycle.go:397`) write `comment`/`status` with only an org-write check; no `editGate`/`rejectManaged`, though the file's `pr_envs.comment/status` own those fields and overwrite them on the next PR open (`prhook/handler.go:488-500`). `pr_envs.enabled` is never persisted at all: read-through at `:476`, while the stack-scoped `Hook` 404s on the panel flag alone (`:92`). Shape: web unchecked box = off for both (`:2654-2655`), api nil = unchanged (`:410-415`).

- **Receive PR webhook — A (two routes, one surface).** `HookConnector` runs `updatePlanComment` and `stackTracksRepo` before dispatch (`prhook/handler.go:157-161`); `Hook` dispatches on the stack id alone (`:110`), so a manually configured repo webhook can open a `pr-N` env on a stack that tracks a different repo, and never gets the plan comment.
