## 2. Candidate services

- **DomainService** (tile domains). `Attach(ctx, tile, DomainSpec{Host, Path, Port, HTTPS, ForceHTTPS *bool, RedirectTo, Rule, Priority, Middlewares}) (*repo.Domain, error)`; `EnsureAuto(ctx, env, tile)`; `SetTLS(ctx, domainID, actor, TLSPatch{HTTPS, ForceHTTPS *bool, CertPEM, KeyPEM *string})`; `Detach(ctx, domainID, actor)`; `ListByTile`. Owns: host+path ownership (`GetDomainByHostPath` + same-tile rule exception), squat check, wildcard-needs-DNS, middleware ref check, managed-tile `SpeaksHTTP`, redirect port default, domain-belongs-to-tile check, then one `ProxyService.RewriteTile`. Calls: ProxyService, DomainResourceService (visible resources for auto), StagingService (when the caller passes stage=true), SettingsService (dns_provider). Call sites: web app ×5, web db ×2, api ×5, config syncDomains, envops.EnsureAutoDomain.
- **DomainResourceService**. `Create(ctx, level, ownerID, host, opts{IncludeEnvOnDefault, ACMEEmail})`; `SetACME(ctx, id, email)`; `SetIncludeEnv(ctx, id, bool)`; `Delete(ctx, id, actor)`; `Visible(ctx, stackID, orgID)`; `AutoHost(...)`. Owns: `ValidateResourceHost`, `HostTaken`, squat (once, for every level), instance owner canonicalisation, managed-owner refusal, Declared adoption, and `ProxyService.RewriteStatic` when an ACME address appears or changes. Calls: ProxyService, OrgService/StackService (owner lookups). Call sites: web ×7 (org, stack, server, wizard), api ×4, cli via api, stackconf applyDomainRes, orgconf applyDomains, seed.
- **ProxyService** (lens 2 owns the inventory). Surfaced here: `RewriteTile(tile)`, `RewriteStatic()` (EnsureTraefik), `Resync()`, `SetStaticOverride(yaml)`, `PutEntry/DeleteEntry`, `SetTrustedProxies(cidrs, trustCF)`, `SetDNSProvider`, `SetRegistryDomain`. Owns the YAML checks and the "restart in background" decision that web and api each re-implement.
- **ProtectionService** (settings shard). Only note here: every settings writer at four levels plus config apply must call `ProxyService.Resync`; today five call sites remember it and tile PATCH does not (calibration B).

## 3. Drift findings

**A1. Attach a custom domain: three rule sets.** web `app/handler.go:1648` vs api `domains.go:35` vs config `plan.go:332,812`.
- Fields: web and config accept rule, priority, middlewares, per-domain port (`app/handler.go:1657-1672`, `stackconf.go:516-537`); api `domainIn` (`types.go:200`) has none, so the CLI cannot set them.
- Squat: web `1714`, config `plan.go:348`; api never calls `CheckOrgSquat`, so the api is the hole the `envops.go:313` comment says is closed.
- Wildcard HTTPS needs `dns_provider`: web only `1688`; api/config write a `*.` host with `certResolver: ledns` (`proxy.go:426`) with no provider configured.
- Redirect domain port: web `1681` and config `apply.go:1639` set 80; api leaves 0 `domains.go:47-53`, rendered as `url: "http://<alias>:0"` `proxy.go:447`.
- HTTPS defaults: web checkbox unchecked = https false **and** force false `1741-1746`; api and config nil = true for both `domains.go:54-63`, `stackconf.go:539-543`; CLI `--no-https` yields https=false, force_https=true.
- Host+path conflict: web allows a same-tile rule entry `1704`; api `70` and web db `589` refuse any match; config keys on host+path+rule `plan.go:958`.
- Managed tiles: web db `582` requires `SpeaksHTTP` and pins the engine port; api has no kind check (a managed tile with an explicit `container_port` passes); config skips non-service `apply.go:1583`.

**A2. Flip HTTPS / cert gate.** web ToggleDomainHTTPS `editGate` `1806` (stages), web SetDomainCert no gate `1846`; api patchDomain `rejectManaged` `205` for both. A `ui_edits: stage` stack accepts the browser toggle and 409s the same CLI `tile domain set`. Also force_https is api-only (`types.go:566`); web and CLI cannot clear the bounce.

**A3. Web domain ownership.** `app/handler.go:1810` ToggleDomainHTTPS and `:1908` DeleteDomain (non-staged) act on `c.Param("domainID")` without checking `d.TileID == a.ID`; `h.load` `430` only proves write on tile `a`'s stack. api `domains.go:92-99` and `lifecycle.go:197-201` resolve the tile from the domain row. SetDomainCert `1852`, the staged delete path `1892` and web db `626` do check.

**A4. Create a domain resource.** Squat only on web org `org/settings.go:545`; web stack `project/handler.go:2460`, web server `server/handler.go:196`, api `domainresources.go:214`, stackconf `apply.go:402`, orgconf `orgconf.go:799` skip it. Api accepts `acme_email` on create (`types.go:226`) and drops it (`domainresources.go:244`); web has no ACME field at all. Instance-level owner id: web = `sv.ID` `server/handler.go:215`, seed = `GetServer("local").ID` `seed.go:37`, api = caller string or "local" unchecked `domainresources.go:178`; reads ignore it (`envops.go:385`), so this is latent, class C only if a second node ever owns a resource.

**A5. Delete a domain resource.** web server `server/handler.go:226` deletes any id posted, including org- and stack-level rows of config-managed owners; api `domainresources.go:264-269` re-runs tenancy + `rejectManagedOwner`; web org/stack restrict to own rows `585`, `2512`.

**B1. ACME account update is lost on the stack file.** `stackconf/plan.go:533` diffDomainRes never emits an acme_email change and `apply.go:439-445` never copies `ACMEEmail` on update, while the org file does both (`orgconf.go:476`, `:826-830`). Changing `acme_email` on a stack-level `domains:` entry after creation is a silent no-op. Api `patchDomainResource` `306` also skips `rejectManagedOwner` that its siblings use, and ignores the `EnsureTraefik` error `338`.

**B2. Registry domain.** web `settings/handler.go:616` runs `registry.EnsureManaged` before `WriteRegistry` so the "registry" alias exists; api `registry.go:319` only `WriteRegistry`. Set from the CLI, traefik routes to an alias the service may not carry. (Registry shard should own the fix.)

**Duplication, no drift.** Proxy escape hatches: `settings/proxy.go:25-48` and `proxycfg.go:39-62` are byte-identical helper pairs. Middleware reference check exists twice: `app/handler.go:1928` and `stackconf/middlewares.go:158`. Trusted-proxy parsing exists in `settings/proxy.go:70-80` and `seed.go:52-62`.
