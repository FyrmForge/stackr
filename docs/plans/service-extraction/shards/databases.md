## 2. Candidate services

1. **InstanceService** (`managedtiles.Service` grown upward). Rows: create, get/list, update settings, set scope, delete, deploy/stop/start, publish connection. Sketch:
   - `Create(ctx, stack, env, in InstanceSpec) (*repo.Tile, error)` — slug rules, reserved/unique, scope derivation (`applyScope`), `NewDB`, `CreateTile`, `PublishConnection`, `Deploy`, status.
   - `Update(ctx, t *repo.Tile, prev *repo.Tile) error` — full struct per the "engine takes a full tile" decision; owns the one `needsRedeploy(prev, t)` rule (today `api/dbs:119-158`, `web/db:519`, `apply:1527`, `orgconf:932`), redeploys when running or errored, republishes vars.
   - `Delete(ctx, t, force bool) error` — held-provisions gate, `TearDown`, `proxy.RemoveApp`, `netpool.ReleaseDB`, drop slices or orphan rows, `DeleteTile`.
   - `Deploy/Stop/Start(ctx, t)` with status write + notifier hook.
   Calls: ProxyService (route rewrite/remove), NotifierService, netpool, deploy engine (for consumer redeploys), VariablesService (PublishConnection).
2. **SliceService**. Rows: provision-for-consumer, attach, detach, cut consumer-less, drop, fork, set public, list, orphan-on-consumer-delete. Sketch:
   - `Provision(ctx, inst, consumer, name string, public bool, wire WireOpts) (*repo.Provision, error)` — `Eligible`, engine cut, then `Wire` (config-managed → publish only; s3 → all outputs; else single ref under a sanitised var), enqueue consumer.
   - `Attach(ctx, src, consumer, wire WireOpts)`, `Detach(ctx, p)`, `DetachAllOf(ctx, consumerID)` (called by TileService.Delete on every surface), `Cut(ctx, inst, env, slug, name, public, onRemove)` with `WaitReady`, `Drop(ctx, inst, dbName)`, `Fork(ctx, inst, src, slug, name)`, `SetPublic(ctx, inst, dbName, public)` looping all rows.
   Calls: InstanceService (ensure shared net), VariablesService/envutil (inject), deploy engine (Enqueue), NotifierService.
3. **InfraResolver**. Rows: resolve address. `Resolve(ctx, path string, scope ResolveScope) (*InfraTarget, error)` accepting both grammars (colon `resolve.go:86` and dotted `slices.go:21`) so config and API address the same set through one function. Calls: store only.
4. Domains on instances belong to the **DomainService** (domains shard) but need one rule from here: `SpeaksHTTP(engine)` and `ContainerPort = Engines[e].Port` (`web/db:581,601`).

## 3. Drift findings

- **Create instance, A.** API `createDB` does not refuse an empty slug (`api/dbs:227-233`), web does (`web/project:1670-1672`); `NewDB` then sets `DBName = ""` (`mt:316`). Web restricts scope to env/stack (`web/project:1700`), API and config allow org (`api/dbs:86-98`, `apply:1707`). Web `CreateDB` lines 1719-1727 are unreachable: both `!p.ConfigManaged()` (1708) and `p.ConfigManaged()` (1716) return first.
- **Get instance, A (return shape).** `listDBs` fills `Path` (`api/dbs:35`), `getDB` does not (`api/dbs:196-204`); `infra get` therefore prints `path: none` (`infra.go:397`).
- **Update settings, A.** Gate: web `rFU` lets an org-scoped instance on a config-managed stack be edited (`web/db:62-67, 483`), API `rM` 409s the same edit (`api/dbs:112`). Validation: web coerces a bad port to 0 (`web/db:486-489`) and a bad `update_policy` to "off" (`510-515`); API 400s both (`api/dbs:121, 178`). Redeploy rule in four copies: web always when running (`web/db:519`), API only on changed fields and only when running (`api/dbs:119-158, 188`), config on `needsDBRedeploy` fields when running or errored (`apply:1466, 1527-1539`) and includes `node_group`/`replicas` which neither web nor API can set on a db, orgconf compares three fields and redeploys only when running (`orgconf:932-945`). `PATCH /apps/:id` (`api/apps:177`) has no `IsManaged` check, so a db row can also be patched through `appPatch` with none of the db rules and no redeploy. CLI `infra set` cannot set `update_policy` (`infra.go:358-365`, `client.go:733-740`) though the API accepts it (`types.go:515`).
- **Set scope, A.** Unknown scope: web silently becomes "env" (`web/db:548-549`), API 400 (`api/dbs:94-95`). Web scope uses `RU` without the org exception (`web/db:535`) while `SetPort` in the same handler uses `rFU` (483): one instance, two gates.
- **Delete instance, B.** Web `Delete` calls `dbs.Remove` (service + `netpool.ReleaseDB`, `mt:570-576`) but never `px.RemoveApp` (`web/db:464-467`), so an s3 instance with a domain (`web/db:572`) leaves its Traefik route behind. API `deleteDB` goes through `teardownTile` (`helpers.go:129-135`), which removes the route but never releases the shared network (`envnet.TearDown`, `envnet.go:199-218`, has no netpool call) and, with `force=true`, deletes the tile while provision and resource rows stay (`store/repo/sqlite/tiles.go:269-282` deletes only variables and bindings). CLI `infra rm` always sends `force=true` (`infra.go:262`). Config `deleteTile` (`apply:1544-1567`) has the API's shape (no held-slices gate, no netpool release). `orgconf:985-995` releases the netpool but skips `TearDown` and `RemoveApp`. `DELETE /apps/:id` (`api/apps:463`) accepts a managed id and skips even the force gate.
- **Deploy / restart, A.** Web `Start` scales to 1, waits, and runs `selfHealProvisions` (`mt:543-561`); API `restartApp` on the same id does `RestartService(name, t.Replicas)` and records status (`api/lc:48-71`), no provision heal. `POST /apps/:id/deploy` (`api/apps:480-493`) enqueues the build engine for a managed tile; behaviour of the engine on a db row not checked. Web `Deploy` runs detached with `context.Background()` (`web/db:249-262`); every other caller is synchronous.
- **Provision / attach, A.** Gate: web `rM` (`web/app:906, 936`) vs API none (`api/dbs:276-351`); the web's config-managed "declare `uses:`" branch (`web/app:874-881`) is dead behind that gate, while the API's publish-only branch (`api/dbs:378`) is live. Var name: web sanitises via `envVarName` (`web/app:966-980`), API injects `in.EnvVar` raw (`api/dbs:314, 401`). Web fixes name "" and public false (`web/app:917`); API takes both (`api/dbs:310`).
- **Provision / attach, B.** s3: API injects the whole `AutoInjectVars` set when `Engines[e].AutoInjectAll` (`api/dbs:381-390`); web injects only `Ref(DefaultOutput)` = `S3_ENDPOINT` (`web/app:868, 885`), so a bucket provisioned from the panel leaves the consumer without bucket/keys variables.
- **Orphan provisions on consumer delete, B.** Web `Delete` (`web/app:1635-1639`) and config `deleteTile` (`apply:1558-1565`) `Detach` every provision the tile consumed; API `deleteApp` → `teardownTile` (`api/apps:463-478`, `helpers.go:129-135`) does not, leaving `provisions` rows with a dangling `ConsumerTileID` and status "active" (`store.DeleteTile` drops bindings only, `tiles.go:273-275`).
- **Cut consumer-less slice, A.** Config waits for the instance (`WaitReady 90s`, `slices:85`), uses `Eligible` (`slices:79`), clones on ephemeral envs (`slices:91-93`) and stamps `on_remove` (`slices:121-131`); API `createInstanceProvision` uses `ServesEnv` (`api/resolve:106`), no readiness wait, no clone rule, no `on_remove`. Two address grammars resolve the same rows: colon via `ResolveTarget` (`resolve.go:86`) for API/CLI, dotted via `resolveFrom` → `ResolveInfraPath` (`slices:21-63`, `infrapath.go:28`) for config.
- **Set slice public, B.** Web (`web/db:425-433`) and API (`api/lc:292-297`) flip every row sharing the `DBName`; config `updateSlice` flips only the representative row `findSlice` returns (`slices:107-114`, `154-180`), so sibling consumer rows keep a stale `Public` and the drawer, which reads the first row (`web/db:333`), can disagree with the bucket policy. Resource re-sync for the siblings not checked.
- **Domains on an instance, A.** Web requires `SpeaksHTTP` and pins `ContainerPort` to the engine port (`web/db:581, 601`); API `createDomain` (`domains.go:35-75`) accepts a managed id with no engine check, takes the port from the body or `t.ContainerPort` (0 for a db), and defaults https/force differently (web: both follow the `https` checkbox, `web/db:602-603`; API: both true unless given, `domains.go:54-63`). Config cannot model a db domain at all (`web/db:565-569`).
- **Org-shared instances, B.** `orgconf.applyShared` engine-replace and undeclared branches (`orgconf:948-955`, `985-995`) delete an org-scoped instance with `dbs.Remove` + `DeleteTile` only: no held-slices check although org scope is the widest sharing, no `envnet.TearDown` of labelled leftovers, no `px.RemoveApp`.
- **Duplication, not drift.** `NewDB` + `PublishConnection` are hand-sequenced at six creation sites (`api/dbs:241-247`, `web/project:1703-1722`, `apply:1197-1220`, `orgconf:967-973`, `envops:81-104`) and `updateTile` must re-call `PublishConnection` because `ReplaceTileVars` wipes it (`apply:1432-1436`). Status bookkeeping after `Deploy` (running/error + slog) is copied in `web/db:251-261`, `api/dbs:249-259`, `apply:1227-1232`, `apply:1473-1485`, `apply:603-608`, `orgconf:975-982`.
