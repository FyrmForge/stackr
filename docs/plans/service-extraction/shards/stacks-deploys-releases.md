## 2. Candidate services

- **StackService** (stacks, one slug rule, one create/delete sequence). Calls EnvService (teardown), PlanService (bind -> plan), StagingService (bind -> drop staged), ProxyService (defaults -> resync), DeployService (rename -> redeploy).
  - `Create(ctx, orgID, name, desc string) (*repo.Stack, error)`: non-empty slug, unique `(org_id, slug)` 409, production env.
  - `Rename(ctx, s *repo.Stack, name string, p *stackconf.Plan) error`: wraps `Applier.RenameStack`; the `moved:` path calls this too.
  - `Delete(ctx, s *repo.Stack) error`: `TeardownStack` + `DeleteStack`.
  - `Move(ctx, s *repo.Stack, targetOrgID string) error`.
  - `BindConfig(ctx, s *repo.Stack, b Binding) error` / `Unbind(ctx, s)`: connector-in-org check, staged-row drop, plan run.
  - `SaveDefaults(ctx, s *repo.Stack, vals url.Values) error`.
- **DeployService** (deployments, the rule "what may be deployed where" once). Calls infra/deploy engine, NotifyService.
  - `Trigger(ctx, t *repo.Tile, trigger string) (id string, err error)`: volume, kind, upper-env and own-repo rules in one place; web, api, prhook, imagewatch, stackconf all route through it.
  - `Rollback(ctx, t *repo.Tile, tag string) (string, error)`.
  - `Cancel(ctx, d *repo.Deployment) error`.
  - `IsLive(status string) bool`: the single terminal/live set for web polling, SSE, cli wait, api release aggregation.
  - `Park(ctx, t, trigger, sha)` / `Release(ctx, d)` for cigate.
- **ReleaseService** (what is built, what runs, promote). Calls DeployService, PlanService (promote with plan), workqueue.
  - `List(ctx, s *repo.Stack) ([]Release, error)`: one derivation of runs/built; web adds the git log on top.
  - `PromoteTarget(ctx, s *repo.Stack, envSlug string) (*repo.Environment, error)`: the rung rule, once.
  - `Promote(ctx, s *repo.Stack, envSlug, commit, planID string, force bool) (PromoteResult, error)`: one enqueue path with one dedupe key and the pending check.
- **PlanService** (config plans). Calls Planner, workqueue.
  - `Run(ctx, s *repo.Stack) ([]*repo.ConfigPlan, error)`, `Approve(ctx, s, cp, force bool) (jobID, error)`, `Reject(ctx, cp) error`, `Preview(...)`, `Export(ctx, s) ([]byte, error)`; one `requireBound` rule for write ops.
- **TileLifecycleService** (stop, restart, one-shot runs, schedule). Calls cluster, jobs, NotifyService.
  - `Stop(ctx, t) error`, `Restart(ctx, t) error`, `RunNow(ctx, t, trigger, actor) (*repo.CronRun, error)` (kind rule), `StopRun(ctx, t, runID) (bool, error)`, `ToggleSchedule(ctx, t) (status string, err error)` (kind rule).
- **ImageWatchService**: `SetInterval(ctx, minutes int) error`; the watcher itself stays engine-side and calls DeployService.Trigger instead of the engine directly.

## 3. Drift findings

1. **Create stack, A.** `web/project/handler.go:165` and `api/stacks.go:40` accept `repo.Slugify(name) == ""` (a name with no letter or digit) and never check for an existing slug, so a duplicate hits `UNIQUE (org_id, slug)` (`store/db/migrations/001_initial.up.sql`, `CREATE TABLE stacks` block) and surfaces as a raw store error. The sibling ops already have the rule: `createEnv` refuses an empty slug (`api/stacks.go:105-108`), `patchStack` refuses empty and duplicate (`api/lifecycle.go:355-361`), `orgconf.applyStack` adopts the existing row (`orgconf.go:856-861`).
2. **Rename stack, B.** `config/orgconf/moved.go:77-78` renames by writing `Name, Slug = m.To` and returns; `Applier.RenameStack` (`apply.go:552-576`) stops every tile under the old name and redeploys the running services, and its comment (`apply.go:530-535`) names the bug this avoids: services keep serving under the old service name. The `moved:` comment (`moved.go:75-76`) relies on the stack apply that follows; whether that apply tears down the old-named services is not checked. The display name is also lost: `Name` becomes the slug.
3. **Bind config repo, B.** `web/project/handler.go:733-742` drops every env's staged rows when a UI-managed stack becomes config-managed, with the reason spelled out ("loaded gun"). `orgconf.applyStack` (`orgconf.go:895-902`) writes the same binding onto an existing UI-managed stack and drops nothing.
4. **Plan now, A.** API requires a live binding and answers 409/422 (`api/config.go:38-53`, `104-111`); web runs `RunAll` unguarded and turns `ErrNotBound` into a generic "Plan failed" flash (`web/project/handler.go:768-769`), and reports only `plans[0]` (`770-773`) where the API returns every plan (`121-127`).
5. **Approve plan, A.** API `requirePlan(write)` refuses a plan whose stack is no longer bound (`api/config.go:49-51`); web `loadPlan` (`web/project/handler.go:827-838`) checks only ownership, so an unbound stack's pending plan can still be applied from the panel. The CLI adds a destructive-plan confirm nobody else has (`internal/cli/cmd/plan.go:314-318`).
6. **Trigger deploy, A.** Web refuses `Kind == "cron"` (`web/deployment/handler.go:78-80`); API has no kind rule (`api/apps.go:480-491`). The engine builds non-KeepAlive kinds and stops at the artifact (`infra/deploy/engine.go:518,655`) and the push hook enqueues cron builds (`web/prhook/handler.go:388`), so the web rule is a panel-only restriction the CLI does not have. Trigger strings also differ ("manual" `:84`, "api" `:488`).
7. **Cancel deployment, A.** Web `loadDeployment` goes through `RequireStackAccess`, which on a POST requires the write role in the tile's org (`middleware/orgctx.go:258-264`); API `cancelDeployment` (`api/lifecycle.go:119-126`) uses `loadDeployment` (`api/apps.go:570-579`) which calls `requireTile(c, d.TileID, false)`, so a read-only member holding a `ScopeAppsDeploy` key can cancel.
8. **Deployment live-state set, A.** Web `Status` and `Stream` treat anything but `queued`/`running` as final (`web/deployment/handler.go:123`, `:198`), so a `waiting_ci` deployment stops the badge poll and closes the SSE while it is still parked. The CLI keeps polling until `done`/`error`/`cancelled` (`internal/cli/cmd/deploy.go:205`), the engine cancels `waiting_ci` (`engine.go:310`), and the API release list counts it as building (`api/releases.go:86`). Four copies of the state set.
9. **Run now, A.** API allows only cron and function (`api/apps.go:502-504`); web `RunNow` (`web/app/handler.go:193-205`) starts a run on any tile kind.
10. **Toggle cron schedule, A.** API refuses `Kind != "cron"` (`api/lifecycle.go:81-83`); web `ToggleCron` (`web/app/handler.go:398-419`) flips any tile's status to `paused`/`idle` and reloads schedules.
11. **Promote with a plan, A.** Web passes `Force: true` unconditionally (`web/project/releases.go:323`); API passes the body's `force`, default false (`api/releases.go:159`). Both hand-build the `ApplyJob` and enqueue under the stack id (`releases.go:322`, `api/releases.go:158`) while the approve path enqueues under the plan id via `stackconf.EnqueueApply` (`job.go:112-115`), so an approve and a promote of the same plan do not dedupe against each other. Neither promote path checks `cp.Status == "pending"` (approve does, `web/project/handler.go:786`, `api/config.go:174`). Web also skips the `h.work == nil` check the API has (`api/releases.go:155-157`).
