## 2. Candidate services this slice implies

1. **TileService** (structural writes; the gate lives here, not in handlers)
   - `Create(ctx, stack *repo.Stack, env *repo.Environment, tc stackconf.TileConf, actor Actor) (*repo.Tile, error)` — one rule set (`validateTile` is already the widest: stackconf.go:995); decides stage-vs-write from `stack.ConfigManaged()`/`UIEdits()`; calls **StagingService** (`staging.Stage`), **JobsService** (`LoadSchedules`), **DeployService** (`Enqueue`, attach-target redeploy), **ProxyService** (`syncDomains`), **BindingsService** (`syncBindings`), **VarsService** (`ReplaceTileVars`).
   - `Update(ctx, t *repo.Tile /*full*/, changed map[string]bool, actor Actor) error` — takes the merged tile (API keeps its `present`-key merge at the edge, decision already taken); owns limits/timeout/healthcheck/source/command/kind-key rules once; side effects from `apply updateTile` 1404: store, `LoadSchedules` on cron, **ProxyService.WriteApp** when proxy-only, **DeployService.Enqueue** otherwise.
   - `Delete(ctx, t *repo.Tile, actor Actor) error` — attached-volume guard, `envnet.TearDown`, **ProxyService.RemoveApp**, **ProvisionService.Detach** per consumer row, store delete, **JobsService.LoadSchedules**. Replaces web 1632-1640, api `teardownTile`, config `deleteTile`.
   - `Gate(ctx, stackID, kind GateKind) (stage bool, err error)` — the two questions from calibration (`editGate` vs `rejectManaged`) as one enum, so `patchApp` stops calling the structural one.
2. **TileLifecycleService** (imperative, never staged)
   - `Stop(ctx, t) error`, `Restart(ctx, t) error`, `ToggleCron(ctx, t) (status string, error)`, `RunNow(ctx, t, trigger, actor) (*repo.CronRun, error)`, `StopRun(ctx, t, runID) bool` — kind checks once (`ToggleCron` cron-only, `RunNow` cron/function-only), cluster call, `UpdateTileStatus`, **Notifier** `Project`+`Containers` on every status change, **JobsService** for cron.
   - `Deploy(ctx, t, trigger) (deploymentID, error)`, `Rollback(ctx, t, tag) (…)`, `Cancel(ctx, deploymentID)` — `UpperEnv` check, cron refusal, tag trim; wraps **DeployService** (`infra/deploy.Engine`).
3. **TileTelemetryService** (reads)
   - `Logs(ctx, t, tail int, follow bool) (<-chan string, stop, error)` — the service-vs-labelled-container resolver, today copied in web 114-125 and api 188-212.
   - `Metrics(ctx, t, window string) ([]repo.Metric, error)` — one range parser; web downsampling stays a view concern.
   - Calls **cluster** (`StreamServiceLogsMarked`, `ListByLabel`, `Logs`) and store only.

## 3. Drift findings

- **Create tile — A.** Kind set: web accepts `volume` (project/handler.go:500-503), api `runpolicy.For(kind)` refuses anything but service/cron/function (apps.go:103), config accepts service/cron/function/managed/volume/slice (stackconf.go:1009-1129). Port on a non-ingress kind: api 400 (apps.go:122), config error (stackconf.go:1015), web stores it (project/handler.go:570, no kind check). Connector from another org: api 400 (helpers.go:114-126), web silently blanks it (project/handler.go:551-555), config `firstNonEmpty(tc.Connector, stack.ConfigConnectorID)` with no org check in `applySource` (apply.go:1890/1897; the org check moved to `githubapp`, parity doc). Cron schedule: web validates only when `kind=="cron"` via form (495), api via `pol.RequiresSchedule` (113-117), config `validateTile` (1072-1081). Defaults: web `TimeoutMinutes:30` for every kind incl. service (568), api 30 only for cron/function (106-120), config `defInt(…,30)` cron/function (1718/1725). Webhook token: web `secrets.RandomHex(24)` (576), api/config `uuid` (apps.go:155, apply.go:1185). Empty slug: web 400 (482), api no check (`Slugify` can return "" → `GetTileBySlug(env,"")` then insert). Managed-stack gate: web inline `p.ConfigManaged()` twice (586, 603), api `managedGuard` (69) — a third spelling of the gate beside `editGate`/`rejectManaged`. Staging: web stages every UI-managed create (592), api writes through (documented at apps.go:56-59), so the same create lands immediately from the CLI and pends from the browser.
- **Update tile settings — A (extends calibration).** Limits: web clamps (`parseLimits` handler.go:157-170), api stores raw incl. negatives (apps.go:251-253), config no rule. Timeout: web clamps to [1,1440] (173-182), api/config refuse <0 only (385/410, stackconf.go:1084) so `0` (=default at run time, apply.go:1718) is storable via api/config but never via web. Healthcheck knobs: web clamps negatives to 0 (1507-1510), api 400 (376), config error (1038). `source_type`: web stores the raw form value (1475), api derives (211-224). `volumes`: web writes the raw textarea (1498), api has no key (`has("volumes")` absent though `TileConf.Volumes` exists, stackconf.go:379), config writes (1732). `storage`: api validates and resolves each attachment (297-321), web never writes `a.Storage` in this form, config `ParseAttachment` only (1067). `command`: config refuses on kinds without `AllowsCommand` (1018), api/web accept on any kind (284, 1453/1461/1511). Cron `image_ref` empty: web accepts (1454), api 400 (445), config error (1012).
- **Update tile settings — B.** Config apply redeploys a service on any non-proxy field change (apply.go:1487-1495) and rebuilds a cron on source fields (1499-1500); web `SaveSettings` (1588-1602) and api `patchApp` (453-460) write the row and stop. Changing port, limits, healthcheck, command, replicas, devices, files over web/api takes effect only on the next manual deploy; the same edit through a config plan deploys. Also (calibration) api skips the proxy rewrite the web and config both do (handler.go:1597, apply.go:1491).
- **Delete tile — B.** Provisions: web detaches every consumer provision (handler.go:1635-1638), config too (apply.go:1559-1564), api `deleteApp` → `teardownTile` (helpers.go:129-135) does not, leaving `provisions.consumer_tile_id` pointing at a dropped row. Attached volume: web refuses to delete a volume tile that is still attached (1616-1618), api has no such guard (463-478) so the target keeps a mount to a volume whose row is gone. Cron scheduler: api reloads (475), config reloads (1026→1100), web does not (1632-1644), so a cron deleted in the browser stays in the in-memory scheduler until another reload (`LoadSchedules` re-reads `ListTiles`, jobs.go:300, so the next unrelated reload fixes it). Confirm: web requires the typed slug (1620), CLI `rt.Confirm` (tile.go:331), api none.
- **Deploy — A.** Web refuses `Kind=="cron"` with "use Run now" (deployment/handler.go:78-80); api `deployApp` (apps.go:480-493) has no kind check and enqueues a build (the engine stops at the artifact, engine.go:651); config `deploy` enqueues crons on purpose (apply.go:1233-1236). Trigger strings differ per surface (`"manual"`, `"api"`, `"config"`), read back as history.
- **Rollback — A (minor).** api trims the tag (lifecycle.go:108-111), web sends the raw form value (deployment/handler.go:97-101). Neither surface applies the `UpperEnv` rule that Deploy applies (apps.go:485, deployment/handler.go:81), so an upper env that must promote can still be rolled back directly; same on both, recorded not flagged.
- **Stop / Restart — B.** Web fires `notifier.Project`+`Containers` after the status write (handler.go:341, 364, 370); api `stopApp`/`restartApp` (lifecycle.go:30-71) write the same status with no notify, so open canvases keep the old badge until something else emits. Web swallows the `UpdateTileStatus` error (339), api returns it (39).
- **Toggle cron — A, B.** api refuses non-cron tiles (lifecycle.go:81-83); web `ToggleCron` (handler.go:398-419) flips `Status` on any tile it is posted to, so a service can be set to `paused`, a status the deploy/reconcile paths were not checked for. Notifier: web 411, api none.
- **Run now — A.** api restricts to cron/function and guards a nil job runner (apps.go:502-507); web `RunNow` (handler.go:193-205) has neither check and `jobs.StartApp` (jobs.go:332-350) does not check kind, so a service tile can be given a one-shot run row from the browser. Trigger strings `"manual web"` vs `"manual api"` (jobs.go:260-261).
- **Scale — A (calibration, extended).** Web-only over HTTP (handler.go:1540-1554); config also owns it (`applyTileConf` apply.go:1742-1743, `validateReplicas` stackconf.go:1030, body not checked against `placement.IsPinned` placement.go:78). api parses `replicas`/`node_group` into `appPatch` (TileConf embed, types.go:81) and drops them silently — a CLI `stackr tile set` cannot express them (`tileSetFlags` tile.go:175-206).
- **Tile logs / Metrics — duplication, no class.** Log resolver copied (handler.go:114-125 vs logs.go:188-212); metric range parser copied (`components.MetricRange` metrics_templ.go:19 vs lifecycle.go:137-142). Same result today.
